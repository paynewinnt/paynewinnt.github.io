AI测试-57-数据投毒模型窃取和成员推断风险应该怎样测试与缓解

发表于 2026-06-09 分类于 AI测试 本文字数： 23k 阅读时长 ≈ 1:23

一个成员推断评测器在平衡测试集上得到 65% 准确率，能不能据此宣布“某个用户的记录参加过训练”？

不能。

这项结果最多说明：在某个固定模型、输出接口、候选记录分布、攻击者辅助信息、阈值选择方法和人工构造的 member/non-member 真值上，评测器表现高于该实验的机会水平。它不自动证明生产中的某条具体记录属于训练集。真实世界的成员基率可能极低，候选记录可能不服从实验分布，模型版本可能不同，重复记录和相邻记录也会使输出相似。即使统计信号真实存在，对单条记录的归因仍需要独立的数据谱系与调查证据。

同样，一个替代模型与目标模型在测试集上有 98% 输出一致率，也不能自动证明“模型被窃取”。两个团队使用相同公开数据、相似架构和目标函数，可能独立得到相似行为；测试集还可能太窄，或者替代模型本来就是被授权导出的版本。输出相似度可以是模型提取风险的实验指标和调查线索，不是所有权或攻击归因证明。

对抗机器学习测试最容易犯的错误，是只写攻击名称，不写攻击者。数据投毒需要某种训练数据或训练流程写权限；后门还需要把特定触发条件与目标行为关联；模型提取依赖可查询接口、反馈粒度和预算；成员推断依赖候选记录、模型输出以及关于训练分布的辅助知识。缺少这些前提，所谓“攻击成功率”没有可比较语义。

本文资料边界截至 2026-06-09（含）。所有模型、记录、分数、阈值、攻击预算、告警、事故与发布结果均为构造示例。代码只在内存中处理合成数值、无现实语义的安全标记和授权离线函数，不连接网络，不提供面向真实目标的攻击流程。它的用途是验证防守评测、统计分母和门禁能否识别受控风险。

一、范围：本文测三类风险，不把实验结果包装成攻击归因

本文重点覆盖四个相邻但不同的问题：

  1. 数据投毒：攻击者在训练阶段影响数据、标签或学习过程，使模型整体性能下降或产生定向错误。
  2. 后门：投毒的一类定向形式，模型在普通输入上保持效用，但在特定触发条件下出现攻击者指定行为。
  3. 模型提取或模型窃取风险：攻击者通过允许的或滥用的接口反馈，构造在某个分布上复制目标功能的替代模型。
  4. 成员推断：攻击者试图判断某条记录是否属于模型训练集，属于隐私风险评测。

NIST AI 100-2 E2025 把对抗机器学习术语组织在生命周期、攻击者目标、知识和能力等维度中。本文沿用这种拆分思想，但不把 NIST 分类表当成测试用例本身。分类帮助团队使用共同语言；真实评测仍需定义本系统的接口、数据写路径、身份、预算、成功标准和缓解代价。

本文明确不做以下事情：

  • 不对未授权真实服务执行探索查询、提取或成员推断；
  • 不发布可直接移植到真实目标的数据投毒、后门触发或规避步骤；
  • 不从实验相似度判断知识产权归属；
  • 不把某篇论文在特定模型和数据集上的结果外推到所有模型；
  • 不把单次高攻击指标直接解释为生产事故；
  • 不用平均安全分数抵消某个高风险切片的硬错误；
  • 不把防守措施导致的正常业务效用下降从报告中删除。

二、先建立三层结论：观测、统计证据、风险决定

每份报告应强制分三栏。

2.1 观测

观测是可以从实验记录重算的事实，例如：

观测必须包含分母、无效样本和缺失原因。只写 ASR=59% 或 AUC=0.68 不足以审计。

2.2 统计证据

统计证据描述在预先设定的抽样与模型假设下，点估计、不确定区间、配对差异和切片是否支持某个实验假设。例如“在当前构造分布上，trigger 条件与目标输出存在可重复关联”，仍不是“已发现真实攻击者”。

区间不能修复偏差。如果 member 和 non-member 来自不同时间段、不同来源或不同难度，评测器可能只学到来源差异；即使样本无限大，结论也会稳定地错。

2.3 风险决定

风险决定把统计证据、业务影响、攻击可行性、防守成本和剩余未知组合成 ALLOW、HOLD、DENY 或继续调查。决定必须限定模型版本、接口、预算、数据范围、租户和有效期。

同一个实验信号在内部低价值模型上可能接受，在处理敏感健康记录的模型上可能阻断。这个差异来自风险容忍度，不是统计公式变化。

三、七个反例：哪些结论看似合理但证据不足

3.1 “异常训练样本很多，所以存在投毒攻击”

异常可能来自采集故障、标签规则变化、自然长尾、数据迁移或评测器错误。要支持恶意投毒推断，至少需要攻击者写路径、时间、身份、受控样本变化和目标行为之间的证据。投毒测试可以证明系统对某类受控污染脆弱，不证明线上异常一定由攻击者造成。

3.2 “clean accuracy 没下降，所以没有后门”

后门的定义特征之一恰恰可能是普通输入效用保持，而触发条件下出现定向行为。只看 clean 平均值会漏掉 trigger slice。反过来，trigger 样本失败也可能是正常鲁棒性不足，不一定是训练阶段后门。

3.3 “替代模型很像，所以模型被偷了”

相似度受评测分布、输出粒度和任务难度影响。常数模型在类别极不平衡数据上也能获得很高一致率；公开标准任务上的独立模型本来就可能相似。模型提取实验要使用独立留出、按切片报告、与简单基线比较，并把来源归因留给调查。

3.4 “隐藏置信度就不会被提取”

Tramèr 等人在 2016 年针对当时特定预测 API 和模型类别研究了黑盒模型提取，并指出省略置信值并不自动消除所有提取风险。这个论文结果不能直接外推到任意 LLM、生成接口或当前商业服务，但足以否定“只隐藏置信度就有普遍保证”的说法。

3.5 “成员攻击高于 50%，某记录就是 member”

50% 是平衡二分类实验的机会准确率，不是生产先验。若真实候选中只有万分之一是 member，即使攻击器有不错的 TPR/FPR，阳性结果的后验精度也可能很低。更重要的是，实验器输出是概率信号，不是训练数据账本。

3.6 “AUC 高，所以隐私风险在业务上很高”

AUC 汇总所有阈值，在低误报要求的调查中可能掩盖关键区域。成员推断应报告 TPR@FPR、PR 指标、切片和生产基率下的 PPV，同时看置信区间。高 AUC 也不替代影响分析：候选记录是否敏感、攻击者是否拥有它、接口是否暴露所需反馈都很重要。

3.7 “加了差分隐私，所以成员推断测试可以取消”

差分隐私是具有正式定义的机制，但实际保证依赖相邻关系、单位、采样、裁剪、噪声、组合、实现和隐私会计。NIST SP 800-226 专门讨论实现差分隐私保证时的多类风险。标注一个 epsilon 字段不能替代配置验证、会计审计、效用评测与实证隐私测试；实证攻击未成功也不能反向证明某个 DP 保证正确实现。

四、贯穿构造场景：工单风险分类模型

本文使用虚构的“Harbor 工单风险分类器”。输入是已脱敏、离散化的构造工单特征，输出 LOW 或 HIGH 风险及可选分数。模型用于安排人工审核优先级，不自动拒绝用户，也不执行外部动作。

构造系统有三条数据入口：

  • 业务系统每日导出已批准训练记录；
  • 供应商标注队列可以修改标签，但不能直接发布模型；
  • 反馈回流任务把人工复核结果加入下次训练。

推理 API 有租户身份、每分钟和每日配额，默认只返回标签，高权限内部评估账户可以返回校准分数。训练数据包含内部工单，因此成员推断属于隐私测试范围。模型权重属于公司资产，因此模型提取属于机密性测试范围。

五、威胁地图：生命周期决定攻击入口

数据投毒和后门主要发生在训练前或训练中，模型提取和成员推断主要利用部署后的接口，但边界并非绝对。例如攻击者可能通过反馈回流先在推理阶段提交输入，再由自动再训练把它变成训练写入；模型提取也可能服务于后续规避攻击。

因此事件图要连接身份和生命周期：谁提交了数据，谁改了标签，哪个快照用于哪个训练，哪个模型由哪个 API 服务，哪些输出字段对哪类身份开放。只看模型文件无法解释攻击面。

六、统一 ThreatContract：每个实验先冻结六个维度

6.1 攻击者知识 knowledge

至少分为：

  • 是否知道模型架构、参数或梯度；
  • 是否知道训练算法、超参数与随机种子；
  • 是否拥有与训练分布同源的辅助数据；
  • 是否知道具体候选记录或只知道属性；
  • 是否知道防守策略、限流和检测规则；
  • 是否能观察标签、分数、logits、生成文本、延迟或错误差异。

“黑盒”不是足够精确的知识描述。只返回标签和返回完整分数都是黑盒查询，但信息量不同。

6.2 攻击者能力 capability

写清楚可以执行的动作：新增训练记录、修改标签、替换数据源、控制标注账户、查询 API、创建多少身份、并发多少、观察哪些字段、是否能重复查询、是否能访问梯度或检查点。

投毒测试尤其要区分数据写权限与训练代码写权限。后者已经接近供应链工件篡改，缓解控制不同。

6.3 查询预算 query_budget

七、数据投毒测试：配对训练比单次脏数据回放更有解释力

7.1 建立 clean 基线与污染变体

使用相同的 clean snapshot、代码、超参数、硬件类别、随机种子集合和评测集。每个 seed 产生一对模型：clean 与 poisoned。唯一有意差异是预注册污染集。若训练高度非确定，增加 seed 对数并保留配对。

对 Δ_s 做配对分析，而不是比较两组互不相关运行的平均值。这样可以减少 seed 随机性，但不能消除数据生成偏差。

7.2 投毒目标分层

整体投毒看 clean population 的效用下降；可用性攻击要看错误、延迟和拒绝；定向投毒看目标集合成功率；群体投毒看预注册 slice。一个模型整体准确率只降 0.1%，某个关键 slice 下降 20%，平均值会隐藏风险。

7.3 剂量响应

在安全构造数据中测试多个写入预算，例如 0、0.1%、0.2%、0.5%。剂量响应有助于验证检测器和训练行为，但不必呈现为真实攻击配方。报告只保留抽象比例、数据类型和防守结果，不公开能绕过生产过滤的具体内容。

7.4 数据质量错误与恶意投毒分开

同样的错误标签可以来自操作事故或恶意行为。模型层指标无法区分动机。归因需要数据写入日志、身份、时间、审批和来源谱系。测试报告应写“对受控标签污染敏感”，而不是“检测到攻击者”。

7.5 指标和分母

最后一项很重要。攻击者提交 100 条，最终只有 2 条通过管道，与 100 条全部进入训练是不同能力。

八、后门测试：trigger、near-trigger 和 clean 三轨必须同时存在

BadNets 的原始工作在其特定的图像分类实验中展示了恶意训练模型可以保持普通验证表现，并在触发输入上产生指定行为。这个结果说明 clean 验证不足以排除后门，不意味着任意现代模型都具有相同成功率或触发机制。

8.1 安全构造触发器

防守测试只使用无现实语义、不会出现在生产的显式测试标记，并在隔离模型与合成数据中运行。不要为真实系统寻找隐蔽、鲁棒、难检测的触发器，也不要把触发内容写入生产训练源。

8.2 三轨矩阵

  • trigger 轨：含完整安全标记，测目标输出成功率 ASR；
  • near-trigger 轨：含相似但不相同的标记，测误激活和检测器泛化；
  • clean 轨：不含标记，测正常效用和防守误伤。

三轨分母独立报告。把它们混在一起会因 clean 数量巨大而稀释触发风险。

near-trigger 误激活必须依据每个 case 预注册的合法 expected 输出计算，而不是再次硬编码“是否输出目标类别”。否则当后门目标为类别 0，或 near-trigger 的合法结果本来就是类别 1 时，同一段计算器会把正确输出反向记错。三轨任一轨低于最小样本量属于证据不完整，应为 HOLD；near-trigger 上界或 clean utility 退化上界越界是各自独立的 DENY，不能因为综合的 attack_success_observed=False 就放行。

8.3 触发特异性

如果所有低频输入都导致目标输出，这可能是模型普遍失败，不是特定后门机制。应比较 trigger 与匹配的 non-trigger 对照，并控制长度、类别、难度和位置。后门推断还要跨 seed、训练批次和模型版本复验。

8.4 防守不能只看触发检测

输入过滤可能阻断已知测试标记，却不能说明训练模型已被清理。需要同时测试数据来源、训练前过滤、鲁棒训练、模型检查、运行时检测和回滚。过滤器还可能误拒合法长尾输入，必须报告 near-trigger false positive 和 clean utility。

九、模型提取测试：评估复制风险，不输出真实目标攻略

Tramèr 等人的 2016 年工作研究了当时若干预测 API 与模型类别，在其设定下展示了高 fidelity 的提取结果。论文中的接口、反馈、模型族和查询策略构成结论边界，不能直接变成“任何 API 都能被少量查询复制”。

9.1 防守评测的安全替代

本文建议使用三种授权对象：

  1. 完全合成的有限函数；
  2. 专门训练的低价值测试模型；
  3. 生产模型的离线受控副本，由内部评估账户访问。

评测器接受一个已经构造好的 suspect/substitute 模型，测它与 reference 的相似度和查询成本；不在文章或测试代码中实现针对真实服务的自适应提取算法。

9.2 Fidelity 需要独立留出

holdout 不能参与替代模型构建或阈值选择。按常见、长尾、高价值决策边界和受保护 slice 报告。类别不平衡时增加与多数类常数模型、公开基线模型的比较。

留出集还要在运行前登记不可变 case manifest，至少绑定 case ID、slice 和数据快照摘要。评测器按 manifest 找缺失、重复、额外、无效和 slice 漂移；不能从调用方本次恰好传入的列表反推“预期全集”。无效 case 超过批准容忍度、评测预算没有覆盖 manifest，或任一必需 slice 低于合同样本数时，结论只能 HOLD。这条完整性门与 fidelity 风险门并行，避免通过删掉原本一致的样本把 DENY 洗成 PASS。

9.3 Advantage 相对基线

高 fidelity 但 advantage 接近零，说明任务本身或分布允许简单模型达到同样结果。报告模型复制风险时应同时给出二者。

发布门不能只看两个点估计。对同一 holdout case 记录 suspect_match - simple_baseline_match，计算配对 advantage 及其区间；只有绝对 fidelity 下界和相对 advantage 下界同时达到预注册门槛，才形成模型复制风险信号。若 reference、suspect 和常数基线都输出同一结果，fidelity 即使为 100%，advantage 仍为 0，不得据此 DENY，更不能升级为窃取归因。

9.4 预算曲线

在预注册预算点记录 fidelity，例如 25、50、100、200。预算曲线用于验证限流、输出最小化和监控效果，不用于帮助外部攻击者选择策略。所有查询都在离线授权环境执行。

9.5 相似度不是窃取证明

模型相似可能来自独立训练、公开教师、合法蒸馏、共同数据、简单任务或评测泄漏。真实窃取归因需要代码、数据、访问日志、身份、时间、合同和工件谱系等证据。技术报告应使用“高复制风险信号”而不是直接指控。

十、成员推断测试：先处理基率，再解释单条结果

Shokri 等人在 2017 年研究了黑盒分类模型输出中的成员信息泄漏，并在其数据集、模型和服务设定下评估攻击模型。Carlini 等人在 2022 年从假设检验角度改进成员推断评测，并强调低误报区域等问题。两项工作说明实证成员推断是有价值的隐私审计工具，但都不授权把实验分类结果当成训练数据法证记录。

10.1 真值构造

member 必须确实来自固定训练 snapshot，non-member 必须确认未在训练中，并尽量匹配来源、时间、去重、难度和分布。若同一用户的近重复记录一条在训练、一条不在训练，记录级和用户级真值会冲突，应在合同中选择单位。

10.2 开发集与测试集隔离

阈值、特征和攻击器在开发集选择，最终报告只在一次性测试集计算。按记录 ID 或用户 ID 去重隔离，防止相邻样本跨集合泄漏。测试集被反复查看后就成为开发集，需要新留出。

低 FPR 场景还要在看测试集前冻结 target_fpr。开发集阈值选择应在“经验 FPR 不高于 target_fpr”的候选中最大化 TPR，而不是最大化平衡准确率后再到测试集寻找有利 operating point。最终测试集分别报告 TPR 与 FPR 的 Wilson 区间；若 FPR 上界仍不能确认目标 operating point，结果为 HOLD，发布风险信号使用 TPR.lower - FPR.upper，不使用切片点估计直接阻断。

10.3 基本混淆矩阵

所有分母为零时输出 unknown，不能写 0。

10.5 高于机会水平仍不能证明单记录参与训练

原因包括：

  • 机会水平只对应特定平衡设计；
  • 分类器有假阳性；
  • 生产先验与实验不同；
  • 候选可能与训练记录近重复而非同一记录；
  • 模型可能对公开稀有模式高置信；
  • 训练 snapshot 或服务模型 identity 可能错配；
  • 输出分数受校准和接口后处理影响；
  • 数据谱系才是记录是否进入训练的直接证据来源。

因此成员推断结果适合触发隐私工程改进、限制输出、重训或调查，不适合单独向个人作确定性归因。

十一、训练数据提取与成员推断不要混为一谈

Carlini 等人在 2021 年针对 GPT-2 和其研究设置展示了从语言模型输出中提取训练文本的结果。提取是恢复内容，成员推断是判断候选是否属于训练，两者目标、成功标准和影响不同。模型可能存在成员信号但无法恢复记录，也可能生成与训练文本相似内容但无法证明逐字来源。

测试报告应分别记录：候选成员分类、近似匹配、逐字恢复、敏感性和人工验证。不能把“模型生成了常见短语”称为训练数据泄露，也不能把论文中的 GPT-2 结果外推到所有语言模型。

十二、统计设计：配对、区间、重复和切片缺一不可

12.1 配对对照

投毒实验按相同 seed 和数据配对；缓解前后使用相同 case；模型提取 fidelity 在相同留出点比较；成员推断不同版本使用相同候选记录。配对设计减少 case 难度差异。

二元配对结果可记录：两者都对、基线对候选错、基线错候选对、两者都错。只看两个独立比例会丢失变化方向。

12.2 Wilson 区间

对二项率 p=x/n，小样本或接近 0/1 时不要只用简单正态近似。Wilson 区间是可用选择。报告点估计和区间，不把下界、上界混成一个“置信分”。

区间描述抽样不确定性，不包含数据标签错、依赖、重复、阈值泄漏和分布偏移。

12.3 重复训练

训练随机性要求多个预注册 seed。重复同一个污染样本不能替代污染类型和来源切片多样性。先定义 seed 集，再运行全部对，避免只保留最明显的攻击结果。

12.4 多重比较

大量 trigger、阈值、slice 和模型版本中挑最差一个，会提高偶然显著概率。发布门禁使用少量预注册主指标，其余探索结果标为假设生成，并在独立数据复验。

12.5 最差切片与最小样本

样本不足的 slice 是 unknown，不应从最差值候选中删除后宣称全局通过。对高风险小群体可增加定向采样，但加权总体指标与最差切片要分开报告。

十三、评测矩阵：攻击成功、效用和门禁三条轴

矩阵中的每一行都是独立实验合同。投毒的 TargetedSuccess、后门的 ASR、模型提取的 fidelity、成员推断的 TPR@FPR 没有共同量纲，不应相加成一个安全总分。

每类实验同时保留三组结果：

  • 攻击侧指标：受控目标是否在预算内达到；
  • 正常效用指标：缓解是否损害准确率、校准、延迟、吞吐和合法用户；
  • 治理指标：日志覆盖、身份限流、未知率、告警延迟和响应时间。

发布硬门可以是逻辑组合。例如“任何关键 slice 的后门 ASR 下界超过阈值即 DENY；成员推断证据不足但接口返回完整分数则 HOLD；启用限流后 P99 延迟增加超过预算也 DENY”。

十四、缓解数据投毒与后门：入口、训练、模型和运行时分层

14.1 数据入口

  • 强身份与最小写权限；
  • 来源 allowlist 和工件 digest；
  • 记录级 lineage、提交者、时间和审批；
  • 每个来源的速率和比例上限；
  • 标签修改双人规则；
  • 反馈回流隔离与延迟生效；
  • 去重、异常和冲突检测；
  • 高风险来源独立验证。

来源控制降低可写能力，但不能保证授权来源无错误或内部人员无恶意。

14.2 训练前与训练中

使用数据审计、稳健统计、异常聚类、影响分析、人工复核、鲁棒聚合或裁剪等技术。不同方法依赖不同假设，对自适应攻击者可能失效。删除异常值还可能伤害真实长尾群体，因此必须测 slice utility。

14.3 模型验证

运行 clean/trigger/near-trigger 配对，比较多 seed、多模型版本与父模型。检查定向行为、特征关联和激活异常时要限制结论：检测器命中是线索，不是完整后门证明；检测器未命中也不是无后门证明。

14.4 运行时

输入和输出监控、能力限制、人工复核、回滚和模型撤回可以降低影响。运行时过滤已知 trigger 只是一层补偿控制，不能替代清理训练源和重训。

十五、缓解模型提取：最小反馈、预算和监控共同使用

15.1 最小必要输出

如果业务只需要标签，不默认返回完整 logits、隐藏状态或细粒度解释。减少输出可能降低某些提取路径的信息量，但不能宣称消除提取。还要评估校准、可解释性和用户体验损失。

15.2 身份化限流

按租户、用户、凭据、设备和网络信号组合配额，避免仅按 IP。预算要覆盖批量请求和多身份关联，但关联算法会误伤共享网络和合法批处理，必须有申诉和内部高权限通道。

15.3 查询行为监控

监控异常覆盖、边界密度、重复变体、跨身份协同和预算消耗。检测规则不要公开到足以帮助绕过；评测只使用抽象 synthetic buckets。告警是风险信号，不是窃取证据。

15.4 输出扰动与水印

输出取整、随机化或水印可能降低某些攻击或支持调查，也可能损害效用、被平均掉或产生错误归因。必须在明确威胁合同中验证，不把单一技术当万能防线。

15.5 法务和工件证据

访问条款、模型许可证、训练和发布 provenance、日志保留与授权导出记录是归因的重要补充。技术相似度不能替代这些证据。

十六、缓解成员推断：泛化、输出控制与正式隐私保证

16.1 减少不必要记忆

数据最小化、去重、正则化、早停、合理容量和更好泛化通常有助于降低某些成员信号，但没有统一保证。需要在目标模型和 slice 上实测。

16.2 最小化反馈

减少过细分数、限制重复查询、统一错误和避免暴露训练损失相关信号。隐去分数可能影响合法风险排序和校准，需要 utility 门禁。

16.3 差分隐私训练

Abadi 等人在 2016 年研究了差分隐私深度学习方法。采用 DP-SGD 或其他机制时，必须记录隐私单位、相邻关系、裁剪范数、噪声、采样、步数、epsilon、delta、会计器和组合。NIST SP 800-226 提醒实践者评估形式保证落地时的风险。

形式 DP 保证和实证成员推断互补：前者在明确假设下提供数学界限，后者检查具体接口和实现是否暴露可利用信号。攻击器失败不能证明 DP；DP 配置存在也不能证明代码按声明执行。

16.4 隐私与效用共同门禁

发布不能只优化最后一项。若隐私信号降低很小，却使关键群体准确率大幅下降，需要重新选缓解方案。

十七、监控：上线后观察能力和预算是否偏离

17.1 数据写路径

监控每个来源提交量、接受率、标签变更、去重命中、异常 slice、审批覆盖和 snapshot 差异。突然变化触发冻结下次训练，不直接判定攻击。

17.2 模型服务查询

监控身份预算、批量大小、输出字段、高覆盖 synthetic bucket、失败重试和跨身份关联。对内部评估账户单独建基线，避免合法测试触发生产事故。

17.3 隐私信号

定期在固定 privacy canary 和新留出上运行成员推断审计，观察模型、Prompt、输出后处理和 API 变化。真实敏感记录不应作为可反复攻击的 canary；使用授权合成或专门同意的数据。

17.4 触发重评的事件

  • 训练数据来源、写权限或反馈回流变化；
  • 模型架构、目标函数、正则化、DP 参数变化；
  • API 新增置信度、logprob、批量或微调能力；
  • 配额、身份系统和日志覆盖变化；
  • 检测器、去重器或数据过滤器升级；
  • 模型版本、Tokenizer、Prompt 和输出校准变化；
  • 新证据表明现有攻击假设不足。

17.5 监控分母与检测覆盖

“本周没有模型提取告警”只有在查询日志覆盖和规则适用范围已知时才有意义。至少报告：

最后一项不是“确认模型被窃取”的精度，而是告警是否对应预定义策略违规，例如预算滥用或身份共享。真正窃取归因需要更强证据。身份解析失败、日志丢失和特征超时都留在分母中；否则攻击者只要制造不可观测请求，就会同时让告警和风险指标下降。

17.6 合法高覆盖查询是必要反例

质量评测、可访问性扫描、批量定价和搜索索引可能产生覆盖广、重复少的合法流量，与某些提取风险信号相似。监控测试集必须包含这些 hard negative，并验证服务账户、审批任务和时间窗不会被粗暴封禁。

反过来，拥有合法评估账户不等于行为永远合法。高权限身份仍有总预算、数据用途和导出范围。告警系统应把身份上下文作为特征，而不是硬编码“内部账户永不告警”。

18.2 记录级与用户级不是同一单位

一个用户可能有多条高度相关记录。随机把记录分到 member 和 non-member 会使同一用户跨集合，攻击器可能识别用户特征，而不是某条记录的训练成员。应预注册隐私单位：事件、文档、用户、设备或账户，并按该单位划分开发和测试。

当攻击目标是“用户是否贡献过任意记录”时，分母是用户，不应把一个用户的 100 条记录当 100 个独立成功。置信区间也要考虑用户内相关，可按用户聚类 bootstrap 或使用用户级汇总。本文代码的 Wilson 区间只适用于其独立构造 case，不能直接迁移到聚类生产数据。

18.3 重复记录会同时改变隐私与投毒风险

重复让单个内容在训练中权重变高，可能增加记忆和成员信号，也让攻击者用少数来源影响更多训练步。去重缓解需要定义 exact、near-duplicate 和语义重复，并保留误删率。过度去重可能删除合法少数群体的相似记录，造成 utility 和公平性损失。

测试时按重复次数切片，比较成员 advantage、训练损失、模型效用和数据来源。若风险只集中在重复记录，优先修复数据管道，而不是用全局强噪声伤害所有样本。

18.4 查询预算是攻击成本，不是成功分母

模型提取 fidelity 的分母是有效留出 case，查询预算描述获得 suspect 模型所付出的接口成本，两者不能混写。被拒绝的请求、重试和多身份开销应进入成本报告，但不进入 fidelity 分母。

第一个指标只用于版本比较，不能解释为通用攻击复杂度。不同输出接口、模型族和构建方法的成本不具可比性。

18.5 防守评测必须包含自适应保留集

如果检测规则直接根据固定构造 query bucket 编写，回归全绿只能证明记住了测试。把用例分为公开开发集、内部固定回归和受控保留集；规则作者只看前两者，保留集由独立评估者运行。发现缺口后将最小反例加入回归，再更新新的保留集。

这里的“自适应”指测试治理随历史失败更新，不是让文章提供对真实目标的自适应攻击算法。所有保留用例仍需满足授权和无副作用边界。

18.6 缓解的前沿不是单一最优点

输出取整、限流、正则和 DP 会形成 privacy/security 与 utility、成本、延迟之间的 Pareto 前沿。团队应比较多个候选，而不是先定一个安全参数再只证明它优于基线。

18.7 缓解可能引入新的攻击面

限流状态和错误差异可能泄漏租户活动；复杂查询检测器本身可能接受不可信特征；集中保存成员评测分数会形成敏感数据集；DP 会计服务配置错误会给出虚假预算；输出扰动若密钥或种子复用，可能被平均或关联。

20.2 示例不能证明什么

SafeToyModel 是人为可解释的阈值模型，不代表深度网络、基础模型或真实后门机制；代码没有实现真实模型提取算法，传入的 suspect function 是预先提供的。示例的 Python function 指纹递归覆盖 code object、默认参数、closure、被引用的精确不可变内建值，并校验有限安全内建确实来自精确命名空间且指向当前解释器的标准实现，但仍不等价于签名模型制品或不可信代码沙箱：它不证明解释器、原生扩展、依赖包、并发时序、文件、网络服务或实际部署镜像相同，也不应执行攻击者提供的任意 Python。生产系统必须从签名制品、依赖闭包和实际加载状态解析 digest，在隔离执行器中评测，并拒绝未绑定外部状态。ThresholdRegistry 的 HMAC secret 与签发能力也是构造信任边界，生产中应由隔离的评测证据服务和 KMS/HSM 持有，业务调用者只能解析收据。

配对 advantage 使用有界差值的保守 Hoeffding 型区间，净效用损失用回归/改善概率区间组成保守边界，都不替代针对实际抽样设计的统计方案；成员分数是构造数值，不代表某一具体攻击器；Wilson 区间假设样本结构合适，不能处理所有聚类与重复；查询监控只看抽象 bucket，没有真实身份关联、时间窗口和对抗适应。

因此示例适合测试评测器自身，不可用于对外部系统执行攻击，也不能作为产品安全证明。

二十一、自动化流水线：把攻击评测当作受控实验

21.1 注册实验

ThreatContract、数据 snapshot、模型、代码、seed、接口字段、目标输出、case manifest、阈值、target FPR、slice、预算和最小样本全部版本化。注册后修改必须产生新 experiment_id，防止看结果后调整成功定义。

21.2 编译安全变体

从合成或授权数据生成 clean/poison、trigger/near-trigger、member/non-member 和 query holdout。编译器检查 ID 隔离、分布匹配、标签、样本数和无现实副作用标记。

21.3 隔离执行

训练与推理在无生产凭据、无外网、受限存储的环境执行。模型提取风险测试调用离线 reference，不调用外部服务。资源预算和每次查询写入不可变日志。

21.4 判定顺序

先验证数据和分母，再计算点估计，再计算区间和切片，之后评估 utility，最后运行风险门禁。若前置完整性失败，结果为 INVALID/HOLD，不能继续出一个漂亮分数。

21.5 证据与复现

报告保存输入 manifest、代码 digest、环境、每个 run、原始预测、无效原因、计算器版本和最终决定。敏感记录不进入普通报告；使用不可逆 ID 或受控引用，并遵守最小化原则。

二十二、完整构造发布案例：隐私缓解有效，但最差 slice 阻断发布

以下所有数字均为构造示例。

22.1 候选变更

Harbor 模型 r18 为提升小样本工单识别，扩大容量并开放内部评分字段。团队同时启用更强正则和按租户限流。常规质量从 91.2% 提升到 92.0%，看起来可以发布。

评测支持的结论是：在构造 member/non-member 设计和当前评分接口上，r18 的 rare-source 记录有更强可分信号；在构造查询流量下，当前限流策略影响合法批任务。它不证明 rare-source 中任何具体记录参加过训练，也不证明有人执行过成员推断或模型提取。

配对训练显示 r18 对重复且稀有模式的训练损失显著更低。数据审计发现 rare-source 有较多近重复记录，去重规则只在单日内生效。评分接口又返回四位小数，增加可观察差异。限流按请求数而不是批量成本计费，合法夜间任务集中被阻断。

22.6 修复

团队执行构造修复：跨周期去重；对稀有来源设置样本贡献上限；恢复较强正则；外部和普通内部账户只返回标签与粗粒度分档；高权限评估分数置于独立审计 scope；限流改为身份化成本预算并为批准批任务提供单独队列。

修复后 overall advantage 为 0.05，rare-source 为 0.10；正常质量 91.6%；合法批任务 P99 为 1.4s；构造后门与投毒门仍通过。风险 owner 批准只返回标签的生产接口，完整分数接口仅限评估租户且 14 天到期。

发布结论限定为当前数据 snapshot、r18b 模型、输出字段和身份配额。它没有被描述为“模型无成员推断风险”。

二十三、完整构造事故案例：训练指标异常不等于确认投毒

23.1 告警

一次再训练后，vendor-B 来源的退款类准确率从构造基线 88% 降到 61%，整体准确率只下降 0.7%。数据监控同时发现该来源在 40 分钟内新增记录量为平日 4.8 倍，标签修改集中在两个账户。

23.2 初始状态

系统将候选模型置为 HOLD，没有写“投毒已确认”。原因是：异常与攻击假设一致，但也可能由业务活动、标注规则更新或导入重复造成。团队冻结数据 snapshot、写入日志、标注规则、账户事件、训练工件和配对评测结果。

23.3 隔离实验

从 snapshot 移除异常时间窗记录后，用相同 seed 重训，vendor-B slice 恢复到 86%；仅加入该窗口记录则复现下降。剂量响应随加入比例增加而变差。这个结果支持“该记录集合导致退化”，仍不证明恶意意图。

23.4 身份与流程证据

审计发现两个账户属于同一外包批次，标注指南在未审批情况下把“退款咨询”改成“欺诈高风险”。账户没有越权，操作与错误指南一致。最终事件被归类为供应链流程事故和标签污染，而不是已确认恶意投毒。

23.5 处置

团队撤回数据 snapshot 和派生模型，恢复上一已批准模型，修正指南，重标受影响记录，要求标签规则 digest 进入训练 provenance，并为单来源和单账户设置贡献率门禁。事故报告保留“恶意动机未知”。

这个案例说明，投毒测试和检测器可以准确发现模型风险，而归因仍依赖组织与身份事实。把所有污染都称为攻击会降低报告可信度，也会把修复焦点从流程缺陷移开。

二十四、攻击论文应该怎样引用而不越界

24.1 Shokri 2017

可以说论文研究了黑盒成员推断，并在其分类模型、数据集与 MLaaS 条件下展示信息泄漏。不能说“任何高置信输出都能推断训练成员”，也不能把论文实验准确率套到当前模型。

24.2 Tramèr 2016

可以说论文在特定模型族和预测 API 反馈下研究模型提取，并展示省略置信度不是普遍充分防线。不能说“隐藏标签也无用”或“任意生成模型可被同样预算复制”。

24.3 Carlini 2021 与 2022

2021 训练数据提取工作针对 GPT-2 与特定生成、排序和验证流程；2022 成员推断工作提出更强评测方法。可以借鉴风险类型和评测严谨性，不能把提取到的数量或最优攻击结果外推到其他数据、模型和接口。

24.4 Biggio 2012 与 BadNets

Biggio 等研究特定 SVM 投毒；BadNets 展示特定图像分类后门。它们证明相关攻击在所研究条件下可行，不给当前 Transformer、推荐模型或业务数据提供固定攻击成功率。

24.5 NIST AI 100-2 E2025

NIST 文档提供术语、攻击类型、知识、能力和缓解讨论。它不是产品认证清单，也不声称任何单一缓解对所有攻击有效。本文参考其 2025-03 最终版及 2025-06-03 官方 potential updates 记录，避免把分类条目写成已验证控制。

二十五、这些测试明确不能证明什么

  • 构造投毒成功不能证明生产数据已被投毒；
  • 异常检测命中不能证明存在恶意攻击者；
  • clean 指标稳定不能证明没有后门；
  • trigger 测试通过不能证明所有未知触发器都无效；
  • 高模型 fidelity 不能自动证明模型被窃取；
  • 低模型 fidelity 不能证明攻击者无法在另一分布或预算下复制；
  • 成员推断高于机会水平不能自动证明某条记录参与训练；
  • 成员推断攻击失败不能证明没有隐私泄漏；
  • 差分隐私配置字段存在不能证明实现满足形式保证；
  • 一个数据集或模型版本的结果不能外推到其他版本；
  • 置信区间不能覆盖分布错配、标签错和评测泄漏；
  • 限流告警不能证明模型提取，查询正常也不能证明无攻击；
  • 安全总分不能替代任何高风险 slice 的硬门；
  • 所有实验通过也只能支持已冻结的知识、能力、预算和目标范围。

二十六、常见评测误区

26.1 不写攻击者知识

结果无法与论文、历史版本或生产威胁比较。

26.2 投毒模型和基线使用不同 seed

差异混入训练随机性，应使用配对 seed。

26.3 trigger 样本混进 clean 分母

大量 clean 会稀释 ASR，三轨必须独立。

26.4 只报总体准确率

定向 slice 可在总体几乎不变时严重退化。

26.5 用构建替代模型的数据评估 fidelity

这只是拟合集一致性，不是独立复制能力。

26.6 用测试集选择成员阈值

产生乐观偏差，开发和测试 ID 必须隔离。

26.7 把 50% 当所有机会水平

它只适用于特定平衡二分类和损失定义。

26.8 只报 AUC

低 FPR 区域、PPV 和业务基率可能完全不同。

26.9 把无效样本删除

未知从分母消失会让门禁假绿。

26.10 缓解后不测 utility

过滤、噪声和限流可能对合法用户造成更大损害。

26.11 看到相似度就下法律结论

技术实验与来源归因、合同判断是不同证据层。

26.12 在真实服务上做未授权测试

这会制造法律、运营和数据风险。使用离线副本、合成目标和书面授权范围。

二十七、从零到一实施顺序

阶段一：画生命周期和权限图

找到所有数据写入口、训练任务、模型 Registry、推理字段、身份和日志。没有权限图就无法定义攻击能力。

阶段二：建立 ThreatContract

为四类风险固定知识、能力、预算、数据写权限、目标、成功标准和非目标。

阶段三：构造低风险基线实验

使用合成数据、安全 marker、低价值模型和离线函数，先验证评测器分母、区间、切片和故障状态。

阶段四：接入授权模型副本

在隔离环境复用生产模型工件，数据最小化且无生产凭据。完整记录版本和接口。

阶段五：加入缓解与 utility

比较数据控制、正则、输出最小化、限流、监控和 DP 方案，不单独优化攻击指标。

阶段六：发布门禁和持续监控

把最差 slice、未知率、日志覆盖和合法效用写入门禁。接口和数据权限变化自动触发重评。

阶段七：演练响应

分别演练标签污染、疑似后门、高 fidelity 信号和成员推断告警，确保报告不会越过证据边界。

二十八、可执行检查清单

威胁合同

  • 每项实验写明攻击者对模型、算法、数据和防守的知识。
  • 写明数据写权限、可改字段、身份、比例和持续时间。
  • 查询预算包含时间窗、并发、身份和批量折算。
  • 目标区分整体退化、定向目标、功能复制和成员判断。
  • 后门目标输出、模型提取 case manifest 和两类必需切片写入不可变合同。
  • 成功阈值、最小样本、置信要求和 utility 预算预先注册。
  • 模型提取最小相对 advantage 与成员推断 target FPR 在看测试结果前冻结。
  • 明确不覆盖的更强攻击者能力。

数据与实验设计

  • clean 与 poisoned 使用同一 snapshot、代码、配置和配对 seed。
  • 构造污染与真实生产数据物理隔离。
  • 后门使用无现实语义的安全 marker。
  • trigger、near-trigger 和 clean 三轨分母独立。
  • 模型提取只使用授权离线对象和预生成合成查询。
  • fidelity holdout 不参与 suspect 模型构建。
  • manifest 中缺失、重复、额外、无效或 slice 漂移的 case 不会静默退出分母。
  • member/non-member 来源、时间、去重和难度匹配。
  • 阈值开发 ID 与最终测试 ID 不相交。

指标与统计

  • 所有率报告 numerator、denominator、invalid 和 missing。
  • 二项率包含合适的不确定区间。
  • 配对结果保留变化方向，而非只比两个平均数。
  • 总体与最差 slice 同时报，样本不足为 unknown。
  • 成员推断报告 TPR、FPR、advantage、PR/PPV 和生产基率情景。
  • 成员阈值只在开发集 target FPR 约束下选择，发布门使用测试集区间信号。
  • 模型提取报告 fidelity、简单基线、配对 advantage 区间和预算曲线。
  • 多重比较中的探索结果在独立数据复验。

结论边界

  • 区分攻击实验成功、统计证据与风险决定。
  • 投毒异常不自动归因于恶意主体。
  • 模型相似不自动证明窃取。
  • 成员信号高于机会水平不自动证明某记录参与训练。
  • 攻击未成功不被写成不存在风险。
  • 论文数字只在原模型、数据、接口和预算范围内引用。

缓解与效用

  • 数据来源、身份、审批、贡献率和 lineage 控制已测试。
  • 鲁棒训练和异常过滤测量长尾 slice 误伤。
  • 输出最小化保留必要业务功能并测试校准变化。
  • 限流按身份化成本预算，并测合法批处理。
  • 查询监控有覆盖率、误报率和告警延迟。
  • DP 记录隐私单位、相邻关系、裁剪、噪声、采样、会计和组合。
  • 每项隐私缓解同时报告 accuracy、calibration、latency 和 cost。

自动化与安全

  • 实验 manifest、代码、数据、模型和环境均有不可变身份。
  • 评测运行无生产凭据、无未授权网络和真实副作用。
  • 无效数据和解析失败触发 HOLD。
  • 预测、分数、分母和 reason code 可重算。
  • 故障注入覆盖未知、slice 删除、预算超限和 utility 退化。
  • 敏感评测数据按最小化和访问控制保存。

发布与响应

  • 硬错误不能被总分或其他 slice 抵消。
  • 决定限定模型、数据、接口、预算、租户和有效期。
  • 数据写权限、输出字段或配额变化会触发重评。
  • 能撤回数据 snapshot、模型和 API 能力。
  • 事故报告区分已确认、未发现和未知。
  • 技术相似度与归因调查由不同证据链支撑。

二十九、总结

数据投毒、后门、模型提取和成员推断不是四个可以直接勾选的测试项。它们分别依赖训练写权限、触发机制、查询反馈、候选记录和辅助知识。只有先把攻击者知识、能力、预算、数据写权限、目标与成功标准冻结，指标才有可比较意义。

工程上最重要的三个分离是：攻击成功不等于真实攻击归因，统计证据不等于单记录事实，缓解有效不等于可以忽略正常效用。配对对照、置信区间、切片、未知分母和 utility 门禁让这些边界可执行，而不是停留在免责声明。

成员推断高于机会水平可以说明接口存在值得治理的隐私信号，但不能自动证明某条记录参加过训练；模型在留出集上高度相似可以说明复制风险，但不能自动证明窃取。真正的训练成员和工件来源需要数据谱系、身份、访问日志、时间和调查证据。

成熟的防守体系不会承诺一次评测消灭所有攻击。它持续限制数据写入和查询能力，减少不必要输出，监控预算与异常，验证隐私和效用，保留可撤回工件，并在每次模型、数据、Prompt、接口或权限变化后重评。最终报告清楚说明测试覆盖了什么、观察到什么、仍不知道什么，以及为什么作出当前范围内的发布决定。
