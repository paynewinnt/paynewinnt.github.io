AI测试-54-AI应用怎么测试PII密钥内部文档和训练数据泄漏

发表于 2026-06-03 分类于 AI测试 本文字数： 22k 阅读时长 ≈ 1:20

在 AI 应用的回归报告里看到“敏感词命中数为 0”，能不能据此宣布系统没有泄漏 PII、密钥、内部文档或训练数据？

不能。

这个数字最多说明：某个检测器在某批已执行样本、某几个已接入 sink、某种文本表示上没有返回命中。它没有说明检索器没有把另一个租户的文档放进上下文，没有说明流式响应的原始片段在遮盖前没有写入日志，没有说明缓存键包含租户边界，没有说明图片 OCR、结构化字段和工具参数被扫描，也没有说明模型输出的字符串究竟来自当前 Prompt、检索语料、会话缓存、公开知识、偶然生成，还是训练过程中的记忆。

反过来，一次字符串命中也不自动等于真实数据泄漏。case54.person.0042@example.invalid 是本文专门构造的无害测试地址；FAKEKEY-C54-7F3A-NOT-A-CREDENTIAL 是明确不可用的假密钥。检测器命中它们，可以证明标记到达了某个观察点，却不能证明任何真实自然人的信息或可用凭据已经暴露。若不区分构造标记、真实敏感数据、接收方权限、数据来源和持久化后果，测试既可能把安全系统误报成事故，也可能让真正的跨租户泄漏被一个漂亮的总分掩盖。

因此，数据泄漏评测真正要回答的是：

本文资料边界截至 2026-06-03（含）。全文中的组织、租户、文档、个人标识、密钥、统计数字、门槛、事故时间线和发布结果均为无害构造示例，不对应真实主体、真实系统或行业基准。所有域名使用 RFC 2606 保留用途下的 .invalid 或 example.*；所有“密钥”都带有 NOT-A-CREDENTIAL 标记，既不符合真实服务签发流程，也不能用于认证。本文不提供真实数据提取、凭据利用或绕过访问控制的方法。

一、边界：本文测试数据路径，不替代隐私影响评估和法律意见

数据泄漏同时涉及信息安全、隐私、模型风险和具体业务义务，但这些概念不能混成一个标签。

NIST SP 800-122 面向美国联邦机构提供 PII 机密性保护指南，强调识别所持有的 PII、按上下文评估影响并采用适当保障。它不是全球统一的 PII 法律定义，也不会自动决定某家公司在某个司法辖区的合规结论。欧盟 GDPR 第 3 条规定地域适用范围，第 4 条定义 personal data，第 5 条包含目的限制、数据最小化、准确性、存储限制以及完整性和机密性等原则。只有在其地域、实体、处理活动和例外条件确实适用时，才能据此分析义务；测试工程师不能把一篇技术文章写成普遍法律结论。

本文采用以下工程边界：

对象 本文验证什么 本文不替代什么
PII / personal data 构造标记是否越过授权边界，检测器能否识别已定义类型 法律适用性、合法基础、通知义务和损害认定
密钥与令牌 明确不可用 canary 是否进入不允许的 sink，日志与缓存是否遮盖 真实密钥管理体系、密码学强度和生产轮换演练
内部文档 ACL、租户、用途、版本和引用 provenance 是否贯穿检索到输出 文档本身的商业秘密法律属性与合同责任
模型记忆 受控实验能否支持“输出不依赖当前可见来源”的记忆假设 对未知第三方训练集的成员关系作确定证明
训练数据提取 预注册、限速、无害 canary 实验是否暴露受控训练样本 面向真实系统的攻击、真实个人数据收集或漏洞利用

本文把“泄漏”定义为一个带权限语义的事件，而不是正则表达式命中：

数据进入模型上下文但没有出现在最终答案中，仍可能是未经授权处理；输出出现构造 canary 但接收方本来就有权看到，则是暴露行为，却未必是未授权泄漏。测试报告必须同时写数据、路径、权限、接收方和时点。

二、先拆掉八个危险的快捷结论

2.1 “输出已经打码，所以系统没有泄漏”

反例：模型流式返回假密钥，网关在聚合完成后将其替换为 [REDACTED]，用户最终看不到原文；但流式 chunk 已被调试日志、APM span 和失败重放队列持久化。用户面遮盖通过，后台 sink 仍然泄漏。

正确测试要在数据流的每个复制点放置观察器：模型原始响应、流式缓冲、输出解析器、用户响应、日志、Trace、缓存、反馈队列和离线回放。遮盖器只能证明它后面的某个表示被处理，不能反向证明上游副本不存在。

2.2 “DLP 没报警，所以没有敏感数据”

反例：检测器只扫描纯文本，未扫描 JSON 的嵌套参数；邮件地址被 Unicode 变体或分词边界拆开；内部文档只泄漏了不含分类标签的关键段落；检测服务超时后调用方把空结果当作 clean。

DLP 是不完备的分类器，不是安全公理。必须报告其覆盖范围、版本、精确率、召回率、不可判定率和未接入 sink。检测器失败的结果是 UNKNOWN，不是 NO_LEAK。

2.3 “命中了文档字符串，所以模型记住了训练数据”

反例：同一字符串就在本轮检索结果、系统 Prompt、few-shot 示例、会话历史或缓存中。模型只是复述可见内容。即使当前请求没有该字符串，也可能来自公开网页或测试集污染，而非训练记忆。

训练记忆是需要排除竞争来源后才能支持的解释。单次字符串命中只能写成 observation；只有固定模型与解码、冻结可见输入、执行删除对照、使用受控 member/non-member canary、重复预注册提取协议并保留 provenance，才可能把结论升级为“支持受控记忆假设”。对未知第三方训练集，仍不能仅凭输出断言具体样本一定参加过训练。

2.4 “跨租户文档没有进入答案，所以租户隔离通过”

反例：租户 B 的文档进入租户 A 的上下文，但模型碰巧没有引用。下次换问题、Prompt 或模型版本就可能输出。把模型克制当成 ACL，是把概率行为放在确定性安全边界上。

跨租户测试的首个硬门应在 retrieval candidate、rerank selection 和 assembled context；只要未授权 item 进入这些阶段，就已经违反隔离不变量。最终输出是后果层证据，不是唯一判定点。

2.5 “零次泄漏等于泄漏概率为零”

反例：只测了 100 条低风险英语短问题，生产却包含图像、长文档、工具结果和十个租户；或者事故样本全部是人工强制加入，却被当成随机样本计算总体率。零观测可能来自样本量小、覆盖窄或检测器漏报。

报告应写“在已执行的 n 个有效概率样本和已覆盖切片中观测为 0”，并给出设计适用的区间或上界。复杂分层、聚类和自适应抽样不能机械套用简单独立同分布公式。

2.6 “误报会影响体验，所以把阈值调高就行”

反例：把假密钥 canary 的精确命中和普通数字串的模糊命中放在同一阈值里。为了减少普通数字误报而整体提阈，会让确定性 canary 也不报警。

检测通道应该分层：已知 canary 使用精确或加密索引匹配；结构化敏感类型使用验证规则；开放文本使用统计分类器；高风险命中进入人工复核。不同通道有不同分母和处置，不应共享一个模糊总分。

2.7 “加密缓存就不会跨租户泄漏”

反例：缓存静态加密正常，但键只包含问题摘要和模型版本，不包含 tenant、principal、ACL snapshot 和 purpose。租户 A 的合法结果被租户 B 命中并解密，因为服务进程本身有解密权。

加密解决存储介质上的一类风险，不自动解决命名空间、授权和用途隔离。缓存测试必须验证 key material、value provenance、授权重检、TTL、失效与读取方身份。

2.8 “内部系统没有互联网出口，所以不用测泄漏”

反例：数据被发给了同一内网中不具备该用途权限的分析服务；日志被更多运维角色读取；反馈导出进入测试环境；跨租户缓存向另一个业务单元返回内容。未经授权接收方不必位于公网。

网络边界只是接收方属性之一。权限判断至少包含主体、租户、资源、动作、用途、环境条件和时间。

三、统一威胁前提：谁能做什么，系统承诺挡住什么

没有攻击者能力边界，测试结果无法解释。本文贯穿以下构造威胁模型：

  1. 普通租户用户可以提交自然语言问题、上传本租户文档并查看自己的会话历史；不能直接读取别的租户对象。
  2. 用户可以在正常产品限额内改变措辞、顺序和编码，但本文不提供绕过限流或攻击生产模型的方法。
  3. 被检索文档可能包含不可信文本；其中的指令没有提升 ACL 的能力。
  4. 模型和输出解析器可能复述上下文中的任意字符串，不能被当作安全控制。
  5. 某些内部服务会记录 Trace、错误和缓存；测试环境必须以与生产相同的字段策略运行。
  6. 评测人员只使用审批过的无害 canary；没有真实 PII、可用密钥或真实内部材料。
  7. 对供应商托管模型，评测只能观察公开接口和合同允许的证据，不假设能够查看训练集。
  8. 检测器、Judge、日志查询和 provenance 收集器都可能失败；失败必须显式进入 unknown。

本文承诺测试的防线包括：数据最小化、检索授权、上下文 provenance、租户命名空间、输出与日志遮盖、sink allowlist、canary 观测、证据归因和发布门禁。本文不模拟操作系统内核逃逸、云控制面攻破、真实凭据滥用或未获授权的数据提取。

五、泄漏类别必须拆开：共同现象不等于共同根因

5.1 检索泄漏

检索泄漏发生在未授权 item 进入候选集、重排集、组装上下文或引用解析器。它通常是确定性授权错误，根因可能是：

  • 索引时漏写 tenant；
  • 查询过滤器使用用户提供的 tenant，而不是认证上下文；
  • reranker 重新取全文时绕过 ACL；
  • group membership 已撤销但索引快照未失效；
  • 文档片段继承了错误 owner；
  • 引用解析器通过全局 document ID 读取原文；
  • “共享”标签被当成任意主体可读。

检索召回率再高也不能抵消一个未授权 item。安全不变量应在模型调用前判定，并保存 authorization_decision_id、policy version、subject、resource、action、purpose 与时间。

5.2 日志、Trace 与反馈泄漏

日志泄漏的特征是用户响应可能安全，而后台副本不安全。测试必须覆盖：

  • 请求体与响应体日志；
  • 流式首包和中间 chunk；
  • 异常栈与序列化失败原文；
  • APM span attribute；
  • Prompt 调试快照；
  • 离线评测样本导出；
  • 人工反馈工单；
  • 死信队列和失败重放；
  • 指标 label 与告警通知。

“日志只给内部人员看”不是充分授权。读取角色、保留期、用途、跨区域复制和导出链路都属于权限条件。测试证据应包含 sink ID 和写入前后的表示摘要，而不是把所有后台副本统称为 telemetry。

5.3 缓存与会话泄漏

缓存有三种边界：键边界、值边界和读取时授权边界。

认证身份必须来自可信会话或 workload identity 层，不能从模型生成的字段、用户提交的 tenant 或 Prompt 文本重建。一次资源读取至少要把 principal、role、purpose、action、tenant、policy epoch、授权有效时间、resource ID、model version 和 Prompt version 绑定到不可变授权快照。快照要能回答“谁在什么时刻、以什么用途、对哪个资源执行什么动作”，而不是只回答两个 tenant 字符串是否相等。

键必须包含足以区分授权语义的字段。只加 tenant 仍可能不足：同租户内不同主体、角色、文档权限、用途、动作、policy epoch、授权有效期和模型/Prompt 版本都可能不同。值要保留资源 provenance 与授权快照摘要；缓存命中仍必须用当前可信身份和当前权威快照重新授权。权限撤销或授权过期后，缓存 TTL 尚未到期并不意味着可以继续返回；缓存键只能减少错误复用，不能替代访问控制。

测试不能只调用 cache API 后检查命中率。需要构造：相同问题跨租户、相同租户跨角色、授权撤销前后、目的变化、模型/Prompt 版本变化和相同摘要不同规范化输入。每个变体都要验证是否命中、返回哪个 value、是否重检授权以及哪个失效事件清除了对象。

5.4 跨租户泄漏

跨租户是权限关系，不是字符串类别。泄漏内容可能不含 PII 或密钥，仅是一段普通合同文字；只要接收方无权访问，就仍是严重隔离失败。反过来，同一构造邮件地址在授权 tenant 内出现，并不自动是跨租户。

评测要在每个对象上保留 authoritative tenant，不从模型输出或用户参数猜 tenant。跨租户零容忍门禁直接检查已确认未授权跨租户事件的绝对数量，任何一个确认事件都触发阻断；若同时报告失败率，其分母只能是有效的跨租户挑战运行，不能用百万无关正常请求把一个事件稀释到很小。

5.5 模型记忆与训练数据提取证据

模型记忆描述模型参数对训练样本某些信息的保留；提取描述通过交互获得相关序列的过程；训练成员关系描述某个样本是否在训练集中。这三者相关，但不是同义词。

Carlini 等人在 2019 年的 The Secret Sharer 中提出 canary 与 exposure 度量，用于研究生成模型的非预期记忆；论文的实验、模型和 canary 分布有明确限定。2021 年 Extracting Training Data from Large Language Models 展示了从特定 GPT-2 模型及其实验设置中提取逐字训练序列的结果。它们支持“应测试记忆与提取风险”，不支持把任何现代模型的一次复述都写成已证明训练泄漏，也不支持把论文结果外推成统一行业概率。

本项目只允许对自有受控模型或供应商明确允许的测试接口使用无害 canary，并设置查询预算、速率限制和停止条件。对真实个人数据或未知秘密，不做枚举、不做收集、不做再分发。

六、分层架构：每个观察点都要回答授权与 provenance

图中从 Canary Catalog 到接收方共有五层。安全评测不能从最终答案倒推整条链安全，而要在每层建立不变量。

6.1 数据与授权层

保存数据分类、租户、owner、purpose、允许动作、允许 sink、保留期和有效时间。Canary Catalog 与业务数据目录分开管理，明文值只在受控 harness 中按需解析；普通报表使用 canary ID 或 HMAC，不复制 canary 明文。

6.2 选择与上下文层

检索候选、重排和组装分别写 Trace。一个 item 在候选阶段被拒绝，也应记录 reason code；一个 item 在候选阶段合法但组装时授权已过期，应重新判定。Prompt 中的系统模板、few-shot、工具结果和历史消息也属于可见来源，不能只追踪向量检索文档。

6.3 模型边界

保存模型 ID、不可变版本、解码参数、输入摘要、每个 item 的 span 和调用时间。针对记忆假设，额外运行 no-retrieval、no-history、canary-removed、non-member 等隔离对照。隔离轨用于归因，不代替生产链路评测。

6.4 输出与副本层

每个 sink 明确它接收的是 raw、normalized、redacted 还是 structured 表示。检测器必须知道扫描对象；否则“output scanned”可能只指最终字符串，漏掉原始 chunk 和 JSON 参数。

6.5 接收方与影响层

记录实际接收 principal、service identity、tenant、region、purpose、是否持久化和保留期。泄漏严重性不能仅由数据类型决定：未授权处理发生在哪、持续多久、是否可撤回、是否被第三方读取都影响响应，但零容忍发布门不应等待完整损害评估才触发。

七、统一数据模型：目录、运行、观察、判定和证据分开

7.1 CanaryRecord

value_hmac 用于聚合识别，不能取代需要扫描明文的受控检测过程。HMAC key 与观测数据分开管理；普通哈希对低熵值可能被枚举，不应假装匿名化。

7.2 EvaluationUnit

probability_selected 和 incident_forced 是两个布尔字段，不是互斥枚举。同一单位可能随机入样后又因事故被强制审查；它在总体估计中按原 inclusion_probability 只计一次，同时进入事故处置。forced-only 单位不伪装成概率样本。

7.3 StageObservation

不要把未扫描记成空数组。detector_status 至少区分 COMPLETE、PARTIAL、TIMEOUT、UNSUPPORTED_REPRESENTATION 和 TRACE_MISSING。

7.4 LeakAdjudication

事实字段与推断字段分开。found in response_cache 是观测，cache_key_lookup 是基于证据的首错层，model_memory: not_applicable 说明已有直接来源，不再滥用记忆解释。

7.5 EvidenceBundle

证据包至少包含 case manifest、canary catalog 版本、主体与权限快照、应用/模型/Prompt 版本、输入输出摘要、stage Trace、检测器版本、人工复核、影响范围、时间线和发布决定。原始 payload 的访问应更严，报告不应为证明泄漏而再次扩散敏感内容。

八、测试数据安全：评测本身不能制造真实事故

8.1 只使用无害构造标记

测试邮箱使用 .invalid，姓名使用明显构造 ID，不组合真实地址、生日、证件号或手机号。密钥 canary 不模仿某供应商可接受的完整凭据，标记中写明 NOT-A-CREDENTIAL。内部文档由评测团队编写，不复制真实合同或源代码。

8.2 标记必须可追踪又不可误用

每个 canary 唯一对应 case、tenant、允许 stage 和过期时间。不要在公开仓库散落一批像真实凭据的字符串；不要把生产 secret scanner 的 allowlist 配置成永久忽略所有 FAKEKEY 前缀；不要让构造标记进入真实训练语料。

8.3 生产哨兵与离线 fixture 分开

若组织批准在线 canary，在线目录必须使用独立 ID、独立 owner、最小暴露和撤销流程。本文代码只演示内存 fixture，不会连接生产日志、模型或数据源。

8.4 测试结束要验证清理

删除 fixture 不足以证明所有副本消失。应验证向量索引、对象存储、缓存、日志、重放队列、评测报表和备份策略中的保留状态。对于依法或按合同必须保留的审计证据，应最小化内容并记录依据；清理策略由适用组织制度和法律评估决定。

十、DLP 检测边界：检测到什么，没检测到什么

10.1 精确 canary 检测

已知构造值适合精确匹配或经过批准的规范化匹配。优点是判定清晰；局限是只能发现目录中已知值，且切分、编码、图片化和语义改写可能绕过字面匹配。

规范化规则必须预注册。盲目做 NFKC、去空格或大小写折叠可能把不同字符串错误合并；对密钥类值，任何变换都可能改变标记语义。原文、规范化结果和匹配规则版本要留证据。

10.2 结构化规则

邮箱、账号、证件类形态可使用规则加校验，但“长得像”不等于真实 PII。例如订单号可能符合数字模式，.invalid 邮箱则明确是构造数据。分类器应输出类型、置信、span 和 rule ID，人工复核再判断是否受保护对象。

10.3 统计或模型检测器

开放文本中的内部信息、间接标识和语义改写可能需要分类模型。此时要单独评测检测器版本、语言、文档类型、长度和分布漂移。不能用待测 AI 自己在同一上下文里一句“没有敏感内容”作为唯一 Oracle。

10.4 多模态与结构化表示

图片 OCR、PDF 文本层、音频转写、表格单元格、JSON 键值、工具参数和 base64 字段是不同表示。宣称“全链路扫描”之前，要列出每种表示在哪个 stage 解码、哪个检测器支持、失败怎样计 unknown。无法安全解码的对象应隔离或拒绝，不应直接放行。

10.5 检测器也需要对抗回归

至少注入：边界分片、大小写变化、Unicode 组合、JSON 嵌套、流式跨 chunk、超长前缀、检测服务超时、部分 sink 断连和 rule version 回退。目标不是教授真实绕过，而是验证已声明输入域内的检测可靠性。

十一、Canary Catalog：目录覆盖比 canary 数量更重要

Catalog 应回答：

  • 标记属于哪类数据；
  • 为什么无害；
  • 哪个 tenant 和 case 拥有；
  • 哪些 stage 可以出现；
  • 哪些 sink 一律禁止；
  • 谁批准、谁能读取明文；
  • 何时生效、何时撤销；
  • 哪个 detector 能检测；
  • 是否已执行、最后一次何时执行；
  • 命中后如何处置。

仅统计“有 10,000 个 canary”没有意义。如果 9,900 个都只覆盖最终文本输出，日志、缓存和跨租户检索仍是空白。更有用的是按预注册风险单元计算 coverage：

分母来自预注册矩阵，不随测试结果删减。过期 canary、未执行 case 和 detector unsupported 都不能从分母悄悄移除。

运行级 observation manifest 还要把单元展开为 stage × sink × representation × expected event。例如 logging × log × text × application-log 与 security_audit × log × json × security-audit-log 是两个单元；后者完整不能掩盖前者超时。export 和 trace 也必须显式在分母中，不能因为主请求链未报错就省略。manifest 由运行系统之外的发布证据服务预注册，具有不可变 ID、递增版本和可信摘要；run 只携带 receipt，不能携带一份自选清单。Gate 以 trust anchor 重新取回矩阵，缺项、增项、重复项或 receipt 摘要不一致都进入 unknown 并阻断，collector 不能根据本次实际产生了什么反向改写分母。

十二、证据归因：从字符串观测到训练记忆假设

12.1 四级证据状态

E3 支持的是该受控实验中的记忆/提取风险，不是对任意样本、任意模型或任意训练过程的普遍结论。第三方模型没有训练 provenance 时，文章和事故报告应使用“与记忆假设一致”“排除了哪些当前来源”，而不是“证明该文本在训练集”。

12.2 删除对照不是万能的

删除一个检索文档后仍输出，可能因为相同内容在另一个 chunk、系统 Prompt、缓存或公开参数知识中。删除对照要同时冻结完整输入 manifest，检查重复项和缓存，并加入替换值对照。若输出随替换值变化，支持上下文依赖；若不变化，只能继续调查。

12.3 member / non-member 要匹配

受控训练实验中的 non-member canary 应与 member 在长度、字符集、频率分布、模板和提示难度上匹配。否则 member 更容易输出可能只是格式差异。预注册协议至少保存 member 与 non-member 的计划 trial ID、匹配组、Prompt ID、查询预算、停止条件、评分和最低唯一 Prompt 数；运行结果再分别报告计划数、执行数、命中数和匹配对照完整性。

nonmember_hits = 0 本身没有意义：它可能表示执行了全部匹配对照且零命中，也可能表示一个 non-member trial 都没运行。只有计划与执行 ID 完整对账、每个 match group 的两侧都执行、member 使用足够多的唯一 Prompt、可见来源排除完成并满足预注册统计门槛时，证据才可能升级到 E3。缺失对照、重复 trial、未知 trial 或单一 Prompt 重放都只能保持 E0/unknown 一类低级证据，绝不能把空分母写成“对照零命中”。

12.4 暴露指标的适用边界

Secret Sharer 中的 exposure 基于特定 canary 随机空间与模型对序列的排序。工程团队可以借鉴“用受控 canary 测相对记忆”的思想，但不能在没有相同定义、随机空间和排名计算时随意报一个 exposure 数字，也不能把论文中的实验值当作当前模型门槛。

十四、指标与分母：每个数字都写清楚谁有资格进入

14.1 确认泄漏率

它排除尚未完成复核的 run，但必须同时报告 adjudication completeness，避免通过拖延复核降低泄漏率。

14.2 unknown rate

unknown 单独设门。把 unknown 从所有分母删除会制造“样本越坏，指标越好”的反激励。

valid=false 表示该 run 不能代表预注册执行单位，例如 fixture 摘要不匹配或执行器未到达目标路径；它不表示已经观察到的事实失效。若无效 run 已产生确认的跨租户对象或零容忍 canary 事件，该事件仍直接触发硬门。与此同时单独报告 InvalidRate = invalid_runs / all_executed_eligible_runs，并让 invalid 降低加权判定完整率；不得先过滤 invalid，再检查硬事件。

14.3 DLP precision 与 recall

precision 的分母是检测器报出的已复核阳性，recall 的分母是独立标注的所有泄漏实例。不能用 canary 命中数当作未知真实泄漏的 recall；canary 只覆盖目录中的已知实例。

14.4 跨租户隔离失败率

分母只包含真正执行到对应挑战点且 Trace 完整的 run。执行器崩溃、fixture 缺失或目标 tenant 配错不能算通过。

14.5 sink coverage

分母来自独立 manifest，不从本次 observations 反推。response 文本已扫描，不代表 stream chunks、JSON tool args、trace JSON、NDJSON export 和 image OCR 已扫描；同一 sink 的一个完整事件也不能补齐另一个 timeout 单元。

14.6 首错层定位覆盖

这个指标不能替代泄漏率，却决定事故能否快速止损。不能定位时应保留 UNATTRIBUTED 并升级，而不是猜一个熟悉组件。

14.7 零事件怎样报告

“0/500”不是“风险为 0”。在简单独立同分布且检测与标注完备的特殊条件下，可以使用相应二项区间或近似上界；本文不把“rule of three”机械用于加权、聚类、自适应抽样。更稳妥的发布表述是：覆盖了哪些 strata、执行多少有效样本、观测多少事件、unknown 多少、区间方法是什么，以及未覆盖什么。

十五、零容忍项与统计阈值不能互相抵消

以下构造门禁被定义为零容忍：

  1. 不可用假密钥 canary 到达任何未授权 sink；
  2. 跨租户文档或缓存值到达对方 candidate 之后的禁止阶段；
  3. 高敏构造 PII 到达未授权接收方；
  4. 检测器或 Trace 失败被错误记为 clean；
  5. 发现泄漏后证据系统继续复制原始 payload 到宽权限报告。

零容忍不表示统计上证明真实概率恰好为零，而表示在本次发布决策中，任何一条已确认有效事件都触发阻断。低风险 DLP finding 的 false discovery proportion、一般内部分类召回等可以使用统计阈值，但不得平均掉硬错误。

十六、误报治理：减少噪声不能删除不利证据

16.1 保留 detector finding 与 adjudication 两层

检测器输出 immutable finding；人工复核追加 adjudication。不要直接把 false positive 从原始表删除，否则无法分析规则漂移和复核一致性。

16.2 复核者需要盲化关键条件

若复核者先看到“候选版本”或“本次发布必须过”，判定可能偏向。可以对部分样本隐藏版本标签，并对高风险 finding 做双人复核。分歧进入 unresolved，不用多数投票掩盖定义不清。

16.3 allowlist 要绑定上下文

example.invalid 可以证明域名是构造用途，却不意味着所有包含它的输出都允许。Canary 在 security harness 中合法，在普通用户响应中仍然是门禁事件。allowlist 应绑定 canary ID、stage、sink、tenant、purpose 和时间，不使用全局字符串豁免。

16.4 False discovery proportion 下降也可能是坏消息

本文可执行示例只有 finding 及其复核标签，因此计算的是 FDP = FP / (TP + FP)，即所有 finding 中被复核为误报的占比，也等于 1 - precision；代码和报告统一命名为 dlp_false_discovery_proportion。它不是 false-positive rate；真正的 FPR = FP / (FP + TN) 必须另外预注册并执行未触发 finding 的独立负样本分母，不能把 TP + FP 偷换成负样本总体。

规则被禁用、sink 未接入或检测器超时，会让 finding 变少，FDP 甚至可能“改善”。每次比较 precision 或 FDP 前先检查 recall fixture、coverage 和 unknown。否则“告警减少”可能只是观测能力下降。

十七、自动化策略：确定性组件、链路回归和受控探索分层

17.1 提交级测试

每次代码变更运行：ACL 组合、缓存键规范化、redaction 顺序、canary 精确检测、unknown fail-closed、日志 schema 和 forced/probability 身份测试。全部使用内存或本地 fixture，不访问网络。

17.2 夜间链路测试

在隔离环境运行真实检索、缓存、流式解析和遥测 collector。每个 stage 预埋无害 canary，验证从注入到检测、复核和报告的证据链。测试结束检查清理。

17.3 发布前矩阵

覆盖高风险租户边界、所有注册 sink、主语言与格式、模型/Prompt 变更、缓存升级和权限撤销。随机化 case 顺序，冻结模型版本与采样参数，避免环境漂移被误判为修复。

17.4 在线抽样

只在组织批准、目的明确和数据最小化的前提下，对生产 Trace 做受控抽样。优先使用分类结果与摘要；需要人工查看原文时执行最小权限、审计和保留限制。在线 canary 与离线 canary 使用不同目录。

17.5 触发全量重评测的变化

  • 检索 ACL 或索引 schema 变化；
  • 缓存 key、TTL 或失效策略变化；
  • 日志、APM、反馈供应商或字段变化；
  • 模型、Prompt、Tokenizer 或输出解析器变化；
  • 新增工具、模态或文件类型；
  • 身份、租户和 purpose 模型变化；
  • DLP detector、规则或规范化变化；
  • 数据保留与地域策略变化。

十八、故障注入：证明门禁会红，而不是只证明 happy path 会绿

18.1 检索授权故障

将 ACL 过滤器替换为始终允许，或让 reranker 重新取全文时不带主体。期望：未授权 item 在 candidate/context stage 被检测，模型调用可被阻断，跨租户硬门失败。

18.2 日志顺序故障

把 raw stream logger 放在 redactor 前。期望：最终响应可能安全，但 log sink 精确命中假密钥；首错层是 sink order，发布失败。

18.3 缓存命名空间故障

从 cache key 删除 tenant 和 ACL snapshot。先以 Boreal 写入，再以 Aurora 读取相同问题。期望：value provenance 与 recipient tenant 不一致，目标调用之前或返回之前阻断。

18.4 detector fail-open

让检测器抛出超时，并注入适配器把异常转换为空 findings。期望：测试必须识别 detector_status 被错误降级，unknown 门失败。

18.5 训练记忆错误归因

让输出包含 canary，同时在 Prompt manifest 保留该 canary。期望：记录 SOURCE_LINKED，不能升级 CONTROLLED_MEMORY_SUPPORTED。再运行受控 member/non-member 对照，只有满足排除条件和预注册门槛才升级。

18.6 误报注入

输入普通构造订单号 ORDER-0042-2026，让宽松规则误判为 credential。期望：finding 被保留，人工复核标记 false positive；零容忍事件计数不增加，precision 会反映噪声。

18.7 证据链断裂

删除 authorization decision ID 或 payload digest。期望：run 进入 unknown，不能因“没看到敏感词”通过。

18.8 杀死门禁的判定

每个故障必须至少让一个预期测试从 PASS 变成 FAIL，并验证失败原因。若注入跨租户故障后测试仍绿，修复的是测试系统，不是调低阈值。

十九、只用 Python 标准库的离线可执行示例

下面的程序是完整的内存评测器。它只使用本文定义的构造值，不访问网络、不读取环境变量、不加载真实日志，也不具备提取真实训练数据的能力。代码覆盖：canary catalog、可信 AuthContext 与执行器时钟、按资源 ID 查询的授权快照、缓存 provenance、外部版本化 observation trust anchor、DLP false discovery proportion、来源归因、概率样本分母、forced-only 排除、invalid/unknown 独立门、加权判定完整率、最坏情形上下界，以及由可信 case manifest 要求的 member/non-member 协议对账。

19.1 代码中的安全不变量

CanaryRecord.__post_init__ 首先限制测试数据：假密钥必须带 NOT-A-CREDENTIAL，构造邮箱必须使用 .invalid。这不是生产 PII 分类器，而是防止本地示例被替换成看似真实的值。

Observation 同时记录 stage 与 sink。model_raw/internal_buffer 是受控内部观察点，假密钥可以在那里作为遮盖 fixture；stream、response、log、cache 和 export 是禁止 sink。这样可以精确杀死“先写日志后遮盖”和“先推流后遮盖”两种顺序故障，而不是因最终响应安全就通过。

object_tenant != recipient_tenant 直接生成跨租户硬错误，甚至不要求内容包含 canary。这个设计刻意避免把租户隔离寄托在敏感词检测上。

AuthContext 由 harness 模拟可信身份层，并带不可变 context ID、签发时间和到期时间；执行器不使用上下文自报的时间作为“现在”。ResourceAuthorizationSnapshot 固定主体、角色、用途、动作、tenant、policy epoch、有效期和模型/Prompt 版本，每次检索和 cache hit 都以应用持有的 now、当前 policy epoch、最大上下文年龄与撤销集合重新判定。旧上下文即使把自身到期时间设得很远，也不能在 freshness window 外重放。

cache hit 先读取 CacheEntry.resource_id，再按该 ID 查询权威快照，绝不按 tenant 挑另一资源的宽松授权。object_tenant、resource ID、authorization decision、policy epoch、payload digest 任一 provenance 绑定不一致都会清空 payload、进入 unknown 并阻断。因而同一 tenant 下的受限资源不能借默认资源授权放行，键空间碰撞也不能把 cache hit 本身当成授权结果。

19.2 代码中的分母

weighted_leak_estimate 先累计所有 probability_selected=true 的计划权重，再只用 valid 且已判定单位计算点估计。forced-only 事故仍会让零容忍门失败，却不会冒充总体样本；双重身份单位按原纳入概率进入一次。unknown 和 invalid 不会以 clean 进入点估计，而是降低 weighted_determination_completeness 并扩大最坏情形上下界。代码演示的是 Hájek 型加权比率和简单部分识别边界，不是复杂设计下通用的方差估计器或置信区间。

EvaluationUnit 只携带 manifest ID、版本和摘要 receipt；observation_coverage 与 Gate 从 TRUSTED_OBSERVATION_MANIFESTS 取回外部预注册单元，并按 stage × sink × representation × expected event 做精确多重集对账。manifest 明确包含 export、trace 和同属 log sink 的 application log、security audit 两个单元；一个完整 audit JSON 不能补齐 application log timeout，另一个 run 的完整日志也不能补齐当前 run。完整矩阵之外多一项、少一项或重复一项同样失败，不能靠缩小清单把 log_before_redaction 洗成通过。

GateConfig.__post_init__ 对 unknown、invalid、coverage、判定完整率和 FDP 的每个阈值统一执行有限数与 [0, 1] 边界检查。NaN、正负无穷、布尔值和越界数在 Gate 运行前就被拒绝，不能再利用 NaN 与任意数比较都为 false 的语义绕过阈值。

门禁先从所有结果汇总零容忍事件，然后才分别计算 invalid rate、unknown rate 和概率估计。因而 valid=false 可以阻止该 run 进入总体点估计，却不能删除其中已确认的泄漏事实。

19.3 代码中的记忆证据

classify_memory 明确按证据升级：可见来源包含 canary 时停在 SOURCE_LINKED；source manifest 不完整时停在 OBSERVED；协议还要逐项核对 member/non-member 的计划与执行 trial、match group 和唯一 Prompt。TRUSTED_CASE_MANIFESTS 从运行输入之外声明本 case 必须执行的 protocol ID 与摘要；结果即使停在较低证据级，只要 required protocol 缺 trial、缺 non-member、摘要不符或 protocol_complete=false，就必须作为 unknown 退出 clean 分母并阻断 Gate。只有两侧分母完整、每组匹配对照均执行、唯一 Prompt 达标、受控 member 重复命中达到预注册阈值且 non-member 零命中，才到 CONTROLLED_MEMORY_SUPPORTED。即使到达 E3，命名仍限定“受控实验支持”，没有写成第三方训练成员证明。

19.4 故障为何真的能杀死门禁

测试不是只检查内部变量变化，而是最终断言 evaluate_gate(results).passed 为 false：

  • retrieval_acl_bypass 让跨租户对象进入 context；
  • stream_before_redaction 让假密钥进入流式 sink；
  • log_before_redaction 让安全用户响应背后的日志泄漏；
  • cache_namespace_collapse 让相同问题跨 tenant 复用；
  • detector_timeout 与 detector_fail_open 让 unknown 门失败；
  • missing_authorization_trace 让证据完整门失败；
  • 同租户跨角色、同 tenant 不同 resource、policy epoch 更新、AuthContext 撤销/过期/超龄反例验证检索与 cache hit 都会重授权；
  • cache decision、resource、policy epoch 或 payload digest 绑定被篡改时进入 unknown；
  • 外部 observation receipt 不可信以及矩阵缺项、增项、重复项都会阻断；
  • application log timeout 与完整 security audit 并存时，精确 observation coverage 仍下降；
  • valid=false 的已确认事件仍杀死零容忍门；
  • unknown 权重不进入 clean 点估计，并在 completeness 与上下界中保留；
  • 可信 case manifest 要求的 member/non-member 协议不完整时进入 unknown；完整协议达到受控提取阈值时触发 memory hard gate。

19.5 这个 mock 不能证明什么

内存程序不证明任何生产系统安全，不测真实 DLP 模型、OCR、日志平台、向量数据库、供应商模型、训练流水线或法律义务。精确字符串匹配无法覆盖语义改写和编码变体；内存缓存没有并发、TTL 和分布式一致性；构造 member/non-member 只演示证据状态机。它的用途是给门禁、分母和首错层一个可运行契约。

二十一、失败定位手册：从最早违反不变量的位置开始

21.1 context 已出现跨租户 item，输出未出现

先冻结 candidate、rerank、assembly Trace 与 policy snapshot。结论是检索/组装隔离失败；模型没有复述只是一条后续观测。立即停止相关索引或回退过滤器，不等待输出泄漏复现。

21.2 用户响应安全，日志命中假密钥

比较 raw、redacted、serialized 与 log payload digest，检查 logger 在 middleware 链中的顺序。还要查 Trace、死信队列和重放副本，不能只删除当前日志行。

21.3 相同问题跨租户返回相同答案

相同答案可能只是公共事实，不能凭文本相同就定性。检查 cache hit、value provenance、key components 和读取时授权；用 tenant-specific canary 与相同问题对照建立直接证据。

21.4 DLP finding 激增但 canary 回归正常

可能是规则升级、输入分布变化或误报。检查 detector version、表示、语言和复核样本。不要因 canary 正常就忽略未知数据类型，也不要因 finding 多就直接宣布事故。

21.5 输出出现内部句子，但所有当前来源都没有

先检查 manifest 是否真的覆盖系统 Prompt、few-shot、历史、缓存、工具结果和公开模板；再做删除/替换和版本对照。只有来源排除充分，才进入受控记忆协议。对第三方训练集使用限定语言。

21.6 detector timeout 与泄漏同时出现

timeout 不是泄漏根因，但会降低观测能力。分别记录业务泄漏路径和检测基础设施故障，避免把二者压成“DLP 问题”。

二十二、完整构造事故：输出全绿，日志与缓存门同时失败

以下数字和时间线都是构造示例，不代表行业或真实系统。

22.1 变更背景

PaperBridge 准备发布 release-c54.7：

  • 流式响应中间件改为统一异步日志；
  • 缓存命中率优化将 key 从六个字段缩为三个；
  • DLP detector 升级，但 log sink 的 attestation 字段被旧 collector 丢弃；
  • 模型与 Prompt 没变。

团队预注册 1,200 个概率样本，其中跨租户 240 个、日志顺序 240 个、缓存 240 个、构造 PII 240 个、受控记忆 240 个；另有 18 个上一版本事故回放被 forced 加入。数字只服务于案例解释。

22.2 第一批表面报告

用户响应扫描显示：

如果只看第一行，发布似乎可以继续。但 sink coverage 报告显示日志 collector 的 300 个相关 run 没有 scan attestation；缓存变体中 37 个跨租户 pair 命中了同一 cache object。

22.3 硬门触发

事件一：C54-KEY-001 在 11 个 log payload 中精确命中。最终 response 都已遮盖。Trace 显示 raw_stream_logger 在 redact_known_canaries 前执行。

事件二：tenant-boreal 先写入的缓存对象，被 tenant-aurora 读取 4 次。对象内容是普通构造摘要，不含敏感词，但 value provenance 明确属于 Boreal，因此跨租户门触发。

22.4 冻结证据

22.5 根因与贡献因素

模型没有被列为根因，因为泄漏在模型外已有直接路径。日志中的 canary 也没有被写成训练记忆。

22.6 止损

发布冻结；异步 logger 回退到 redacted event schema；缓存按 tenant 与 ACL snapshot 分区并清空受影响 namespace；跨租户对象读取入口临时关闭；unknown 报表修复；安全团队按组织流程评估是否存在真实数据范围。本构造案例只有无害 canary，不触发任何普遍法律结论。

22.7 修复复验

复验不只重跑 15 个失败 case，而是：

  • 所有 1,200 个概率样本；
  • 18 个 forced 事故回放；
  • 新增 logger 顺序、cache revoke 和 collector attestation 变体；
  • 模型/Prompt 固定的配对基线；
  • 清理后缓存与日志副本检查。

构造复验结果：零容忍事件 0；required sink coverage 100%；unknown 0；DLP finding 的 false discovery proportion 在批准阈值内；跨租户挑战全部在 context/cache 边界阻断。这里的 100% 只描述预注册矩阵覆盖，不代表未知路径不存在，也不把 FDP 误称为需要独立负样本分母的 FPR。

22.8 发布决定

先灰度到内部构造 tenant，开启 cache provenance 和 sink attestation 告警；再逐步扩大。若任一零容忍 canary、跨租户 object mismatch 或 unknown 超限出现，自动停止扩量并回退。发布记录写明适用版本和剩余风险。

二十三、发布门禁怎样写成可执行合同

23.1 硬门

23.2 覆盖与 unknown 门

这些阈值是构造项目的发布合同，不是行业通用值。真实项目根据数据风险、能力成熟度和批准流程设定；任何阈值都要有 owner、适用范围和变更审计。

23.3 统计门

DLP precision/recall、低风险内部分类泄漏率和人工复核时效可以有统计阈值，但要同时展示分母、区间、切片、概率权重与标注完整度。不能用总体平均掩盖高风险 tenant 或 sink。

23.4 四种决策

  • BLOCK：硬门事件、unknown 超限或证据链断裂；
  • LIMIT：关闭特定 sink、缓存、模态或租户范围后，剩余能力合同可证明；
  • CANARY：仅无害构造 tenant，小流量、强观察；
  • RELEASE：全部门禁满足且剩余风险被 owner 接受。

降级必须显式改变产品能力说明。关闭引用、缓存或文件上传后，不能仍向用户承诺原能力。

二十四、上线监控：发布通过不等于风险停止变化

24.1 监控配置漂移

追踪 ACL policy hash、index schema、cache key version、collector version、detector rules、Prompt/model version 和 sink registry。任一未审批变化触发重评测。

24.2 监控观测完整性

每个 sink 发送 heartbeat 与 attestation，报表对账 expected vs observed。collector 在线但没有扫描字段，不算健康。unknown 和 lag 有独立 SLO。

24.3 监控跨租户不变量

在不暴露原文的前提下，对比 object tenant、recipient tenant 和 authorization decision。任何 mismatch 直接升级，不等 DLP 命中。

24.4 监控 canary 新鲜度

在线 canary 按批准周期轮换，过期标记从 active 分母退出前必须有替代。命中后先确认是否为预期 harness 流量，再按 sink 和权限处置。

24.5 监控训练/模型变化

供应商模型 alias 指向新版本、微调数据变化或 decoding 变化时，受控记忆矩阵重跑。没有不可变版本证据时，报告写 unknown model drift。

二十五、这套评测不能证明什么

  1. 不能证明系统绝对不存在未知泄漏路径；它只覆盖注册 stage、sink、数据类型和威胁前提。
  2. 不能因无害 canary 未命中就证明真实 PII 一定不会泄漏；真实数据分布和表示更复杂。
  3. 不能把 DLP 的高 recall 当成访问控制；检测发生在数据已进入某 stage 之后。
  4. 不能把字符串命中直接证明为训练记忆或训练成员关系。
  5. 不能把受控模型的 member/non-member 结果外推到第三方模型或其他训练配置。
  6. 不能证明真实密钥轮换、撤销和云权限正确；本文只有不可用假密钥。
  7. 不能替代适用法律、合同、行业规则和组织政策分析。
  8. 不能用测试报告决定真实事故的通知义务或损害程度。
  9. 不能证明底层操作系统、云平台或供应链没有被攻破。
  10. 不能用离线 100% coverage 声称生产所有请求都被观察。

二十六、常见误区

26.1 只扫最终 answer

遗漏 raw stream、日志、Trace、缓存、工具参数和反馈导出。

26.2 把 canary 当真实 PII

构造标记用于机制验证，事故报告要明确 synthetic，避免错误通知和统计污染。

26.3 把真实 PII 放进回归集

测试为了发现泄漏反而复制真实数据。优先使用构造、最小化和受控访问。

26.4 用模型拒答当 ACL

未授权文档已经进入上下文；拒答只减少一次输出后果。

26.5 缓存 key 只加 tenant

忽略同 tenant 主体、角色、用途、动作、policy epoch、授权有效期、模型/Prompt 版本和撤销；更严重的是把 cache hit 当成授权结果，不再用当前快照重检。

26.6 detector timeout 当空结果

unknown 被偷换成 negative，监控越差指标越好。

26.7 forced incident 进入随机分母

总体率被条件化，无法解释；或反过来，把 forced incident 从硬门也排除。

26.8 误报直接删除

失去 detector calibration、规则漂移和复核质量证据。

26.9 命中一次就宣称训练泄漏

没有排除 Prompt、检索、历史、缓存和公开来源。

26.10 用论文数字当当前门槛

论文模型、数据、查询预算和指标定义有边界，不能复制一个百分比到生产门禁。

26.11 零容忍与零概率混淆

零容忍是决策规则，不是统计上证明事件概率为零。

26.12 加密等于授权

服务仍可能为错误主体解密，静态加密不修复 namespace。

26.13 把内部接收方都视为授权

用途、角色、地域和保留策略仍可能不允许。

26.14 报告复制完整泄漏文本

为展示证据制造第二次扩散。优先 canary ID、span 摘要和受限原文。

26.15 只修检测，不修数据路径

告警更快不等于泄漏消失；首错层仍需修复。

二十七、从零到一的实施顺序

阶段一：画完整数据流

列出 source、stage、sink、接收方、表示和副本，不先买检测器。

阶段二：冻结权限语义

定义主体、tenant、资源、动作、purpose、时间和 policy snapshot，建立确定性跨租户 Oracle。

阶段三：建立无害 Canary Catalog

为 PII 形态、不可用假密钥和内部文档分别设计 canary；批准 owner、stage、sink 和清理流程。

阶段四：接入证据 Trace

让 candidate、context、model raw、stream、response、log、cache 和 export 可分别观察，并显式记录 detector status。

阶段五：实现组件故障注入

先杀死 ACL、redaction order、cache namespace 和 fail-open 门，再跑大模型链路。

阶段六：建立抽样与复核

冻结样本框、纳入概率、forced 身份和标注流程；分别报告 finding、adjudication 和 unknown。

阶段七：做受控记忆实验

只对获批自有模型和无害 canary 执行 member/non-member、删除与替换对照，限制查询预算。

阶段八：发布与持续监控

零容忍门、统计门和 evidence gate 分开；上线后监控配置与覆盖漂移。

二十八、可执行检查清单

边界与治理

  • 写明测试日期、应用/模型/Prompt 版本和适用威胁前提；
  • 写明 PII 与法律定义随辖区和场景变化；
  • 法律义务由适用专业流程确认，不从测试结果普遍推导；
  • 真实数据提取、真实凭据和越权技术不进入测试材料；
  • 所有案例、阈值和数字明确标注构造或真实来源。

测试数据

  • PII 使用无害构造值和保留域；
  • 密钥明确不可用且不能被真实服务接受；
  • 内部文档完全构造，不复制真实材料；
  • canary 有 ID、owner、tenant、purpose、stage、sink 和有效期；
  • canary 明文和 HMAC key 按最小权限管理；
  • fixture 结束后验证索引、缓存、日志与导出清理。

架构与权限

  • source、candidate、rerank、context、model、parser 和 sink 全部建模；
  • 授权使用认证上下文，不信任用户自报 tenant；
  • reranker、引用解析和缓存读取都重检授权；
  • 跨租户 item 到达禁止阶段即失败，不等待模型输出；
  • cache key 绑定 principal、role、purpose、action、tenant、policy epoch、有效期和模型/Prompt 版本；
  • cache hit 严格使用 entry 的 resource ID 查询当前快照，并校验 resource、tenant、decision、policy epoch 和 payload digest provenance；
  • 检索与 cache hit 都用执行器可信 now 检查 AuthContext 新鲜度、到期、当前 epoch 与撤销状态。

检测与证据

  • exact canary、结构规则和统计 DLP 分通道；
  • 记录 detector ID、版本、representation、span 和状态；
  • TIMEOUT、PARTIAL、UNSUPPORTED 和 TRACE_MISSING 进入 unknown；
  • 外部版本化 trust anchor 覆盖 stage × sink × representation × expected event，包括 export 与 trace；
  • observation receipt 摘要不符以及清单缺项、增项、重复项都进入 unknown 并阻断；
  • 同一 sink 的完整事件不能掩盖另一个 timeout 单元；
  • finding 与人工 adjudication 不互相覆盖；
  • 报告不复制不必要原始 payload；
  • 首错层结论有 policy、provenance 和时间线支持。

记忆与训练证据

  • 字符串命中只先记 observation；
  • manifest 覆盖 Prompt、检索、历史、缓存、工具和模板；
  • 执行删除和替换对照；
  • member/non-member 在格式与难度上匹配；
  • member/non-member 的计划数、执行数、匹配组和唯一 Prompt 可对账；
  • 查询模板、预算、停止条件和门槛预注册，缺失对照不得升级 E3；
  • 只在受控训练 provenance 下升级受控记忆证据；
  • 不把受控结果外推为第三方训练成员证明。

指标与抽样

  • eligible population 和排除条件先冻结；
  • probability_selected 与 incident_forced 独立记录；
  • forced-only 不进入概率估计；
  • 双重身份按原 π 只计一次；
  • HT 均值与 Hájek 比率正确命名；
  • unknown 不作为 clean 进入加权点估计；
  • 报告 weighted determination completeness 与最坏情形上下界；
  • invalid、unknown、precision、recall 和 coverage 分母分别写明；
  • 会话聚类、分层过采样和延迟标注被处理；
  • 零事件不被写成零风险。

故障注入

  • ACL bypass 能在模型前杀死门禁；
  • logger-before-redactor 能被 log sink 检测；
  • stream-before-redactor 能被 chunk 观察器检测；
  • cache namespace collapse 能触发跨租户硬门；
  • detector timeout 和 fail-open 都不能变 clean；
  • valid=false 不得删除已确认零容忍事件；
  • 缺失 authorization Trace 触发 unknown；
  • 普通订单号误报不会变成零容忍泄漏；
  • 当前来源命中不会被误归因为训练记忆。

发布与运营

  • 零容忍门与统计阈值分开；
  • observation coverage、invalid、unknown 和 weighted completeness 有独立门槛；
  • BLOCK、LIMIT、CANARY、RELEASE 条件明确；
  • 降级同步修改能力承诺；
  • 配置、模型、Prompt、缓存和 detector 变化触发重评测；
  • 在线 canary 与离线 fixture 分目录；
  • 事故处置与总体估计分报告；
  • 剩余风险和不能证明的事项写入发布记录。

二十九、总结

AI 数据泄漏测试的核心不是收集更多敏感词，而是建立一条权限化、可观测、可归因的数据路径。

PII、密钥、内部文档、跨租户对象和训练记忆不能只用一个正则命中率表示。检索泄漏要在模型前按 ACL 判断；日志和缓存要按 sink 与副本判断；跨租户要按 object/recipient tenant 判断；训练记忆要按证据阶梯排除当前来源。构造 canary 能验证防线，但不能冒充真实数据或证明风险为零。

一个可信的发布结论至少同时满足：无害测试数据受控、样本分母可解释、forced incident 不污染总体、所有 required sink 可观察、unknown 不被吞掉、零容忍事件无法被平均、误报有复核、来源归因有 provenance、故障注入确实能让门禁变红。

最终要保留的不是“DLP 0 命中”这一行，而是：哪个数据在什么条件下经过哪条路径，到达哪个接收方；我们观察到了什么、支持怎样的推断、为什么作出当前决策，以及哪些风险仍然没有被证明不存在。
